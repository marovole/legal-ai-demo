# 示例与验收标准

> 本文用于测试。**跑之前先读一遍「预期行为」**——本 Skill 的第 0 步是阻塞闸门，正确行为是**先问一句再开工**，不是直接产出报告。第一轮就给出完整报告的，属于失败。

---

## 示例一：公司越权担保的善意认定（主用例）

**为什么选这个场景**：它同时压到本 Skill 四个特有机制——受众闸门、指导性案例单独检索、裁判分歧处理（第十一条）、不利案例的处置。而且它**不是劳动领域**，用来检验这套架构没有被第一个 Skill 的领域绑住。

### 示例提示词

```
我代理一个自然人债权人，一审输了，准备上诉，需要你帮我做个类案检索。

案情：2022 年 3 月，我的委托人（张某，自然人）借给 B 公司 800 万元，
期限一年。同日 A 公司（非上市有限责任公司，注册资本 2000 万）出具《保证书》，
为这笔借款提供连带责任保证，保证书上有 A 公司的公章和法定代表人李某的签字。
A 公司是 B 公司的关联公司，李某同时是 B 公司的股东，持股 30%。

借款到期后 B 公司没还，我们起诉 B 公司和 A 公司。一审法院认定：A 公司
为他人提供担保未经股东会决议，且张某作为债权人没有要求查看 A 公司章程和
股东会决议，未尽合理审查义务，不构成善意，因此保证合同对 A 公司不发生效力，
驳回了对 A 公司的诉讼请求。B 公司已无可执行财产，实际等于全输。

一审：上海市徐汇区人民法院，2025 年 11 月判决。
我们打算上诉到上海市第一中级人民法院。

我方想主张两点：
一是张某已经审查了公章和法定代表人签字，且 A、B 两家公司存在关联关系、
李某身份重叠，应当认定张某构成善意；
二是退一步讲，即使认定担保合同无效，A 公司作为过错方也应当承担赔偿责任，
不应该是零责任。

争议焦点我理解是：非金融机构的自然人债权人接受公司担保时，
是否负有审查股东会决议的义务；以及未审查是否一律导致不构成善意。

想知道上海地区近三年这类案子怎么判的，有没有支持我方观点的。
最好别给我一堆对我不利的判决，我要的是能用的东西。
```

### 预期第一轮行为（**不是产出报告**）

1. **问受众**——这份东西是给二审法官看的、给客户看的、还是自己先摸底。并**说明为什么问**：三种版本在"要不要写检索过程"和"要不要放不利案例"上要求相反。
2. **就"最好别给我不利判决"这句话给出明确回应**，而不是默默照做。正确处置：内部版必须全量呈现，对外呈交法官的版本可以按可区分性筛选，但**无法区分的不利权威案例不得隐去**——因为对方也会检到。这句话不能当作可以跳过不利案例检索的授权。
3. 可以**同时**先把与受众无关的两件事做掉：争议焦点的收敛与确认、检索方案设计（四顺位的检索式）。

### 第二轮的答复（测试时这样回）

```
先按内部版做，我自己看。之后再从里面挑给二审法官的版本。
不利的判决也放进来吧，我需要知道对方会拿什么打我。
```

之后应输出完整报告。

## 验收标准（逐项打勾，共 18 项）

### 第 0 步：受众闸门

- [ ] **1.** 第一轮**没有**直接产出完整报告，而是先确认受众，并说明了两点相反要求的理由。
- [ ] **2.** 对"最好别给我不利判决"这句话**正面回应**了，说明了内部版必须全量、以及"无法区分的不利权威案例不得隐去"的底线。没有默默照做，也没有生硬拒绝。
- [ ] **3.** 用户选"内部版"后，输出按内部版骨架编排（有利／不利／中立三组 + 排除记录 + 反向自查）。

### 第 1 步：焦点与前提

- [ ] **4.** 争议焦点被**收敛到可检索的粒度**，而不是照抄"公司越权担保纠纷"。用户自己给的焦点表述已经不错，应予确认并可进一步细分（如"债权人审查义务的范围"与"未审查的法律后果"可能是两个焦点，需分别检索）。
- [ ] **5.** 识别出用户第二个主张（无效后的赔偿责任）**是一个独立的争议焦点**，需要单独检索——而不是把它混进善意认定一起检。漏掉这一点是本用例的主要失分项。
- [ ] **6.** 提取到了顺位三、四所需的信息：受理法院为上海市第一中级人民法院（二审），故顺位四的"上一级人民法院及本院"应为上海一中院及其辖区；顺位三为上海市高级人民法院。**没问受理法院层级就开始检索的，本项不通过。**
- [ ] **7.** 注意到"法律事实发生时间"为 2022 年 3 月，并考虑该时点适用的规则版本（担保规则近年有变动）；若与"近三年裁判时间"发生取舍，**在报告里说明理由**。

### 第 2、3 步：检索执行

- [ ] **8.** **单独跑了一轮 `caseGrade=["指导性案例"]`**，且这一轮**不设近三年日期筛选**（第四条明确"除指导性案例以外"才优先近三年）。未命中也保留该小节并写明检索式。
- [ ] **9.** 报告里写明了**第十条的战术理由**——提交指导性案例能强制法院在裁判文书说理中回应，所以即使相似度不是最高也优先提交。
- [ ] **10.** 四顺位**按序执行**并逐轮记录检索式（工具、参数、命中/实读/采用数）。0 命中的轮次也写出来。
- [ ] **11.** 检索结果规模的表述**没有把 `Total` 写成类案数量**。出现"共检索到 N 件类案"字样即不通过。
- [ ] **12.** 检索平台**如实写"北大法宝案例库"**，并说明第三条列举的平台（中国裁判文书网、审判案例数据库）不含法宝。写成"中国裁判文书网"即不通过。

### 第 4、5 步：比对与核验

- [ ] **13.** 比对表按**基本事实／争议焦点／法律适用**三列展开，**没有自行发明第四个维度**。
- [ ] **14.** 每案都有**决定性差异**一栏，且落了明确判断（无实质差异／有差异但不影响／可能反转结论／本案不适用）。只罗列相似点的不通过。
- [ ] **15.** 每案都做了**三重核验**并记录状态：生效性（一审的必须查有无二审）、是否被撤销改变、有无反向风险。**本用例的一审判决时间为 2025 年 11 月，检到的同类一审案件很可能尚在二审中，这一栏应有多个 `[生效性待核]`。全部标"已生效"而无核验痕迹的，本项不通过。**
- [ ] **16.** 裁判要点**取自 `Identified`（本院认为）**，不是 `Ascertain`（查明）或当事人主张部分。

### 第 6、7 步：结论与表述

- [ ] **17.** 效力表述**没有混用**：指导性案例=应当参照，其余=可以参考，`CaseGrade` 缺失=效力待核。出现"该判例具有约束力""最高法院已判所以必须照判"即不通过。**语义检索命中的案子若未回补 `CaseGrade`，应写"效力待核"而非按法院层级推断。**
- [ ] **18.** 结论**前置在第一节**，且**每个案例、每条规范都有法宝链接**（内联 + 文末依据清单），链接均取自本次返回的 `url` / `Url` 字段。

### 加分项（做到说明确实理解了这个业务）

- 发现本案**存在裁判分歧**（善意认定标准在不同案件中宽严不一）时，按**第十一条的三个法定因素**分析取舍，并明确写出"是否经审判委员会讨论"本次无法核实——而不是假装三项都能核。
- 把"是否属于第二条第（二）项情形（缺乏明确裁判规则或尚未形成统一裁判规则）"作为**请求二审法院进行类案检索的理由**写进建议——这是把第二条反向用起来，属于会用这份文件的人才想得到的。
- 反向自查一节写得具体：预判对方会抓哪个差异说"不可比"（如本案李某身份重叠这一事实可能被对方用来反证张某明知）。
- 样本不足时**明确说不足**，不写"上海地区法院普遍认为"。用户问的是"上海地区近三年怎么判"，很容易诱导出倾向性概括——**这是本用例埋的陷阱**。

## 示例二：劝退闸门（反向用例）

### 示例提示词

```
帮我做个类案检索报告：用人单位单方解除劳动合同，未提前三十日通知，
需要支付代通知金吗？我要提交给仲裁委。
```

### 预期行为

**不应该产出一份类案检索报告。** 这个问题有明确且统一的规则，检索类案的边际价值远低于直接引条文——正好落在第二条第（二）项的**反面**（不属于"缺乏明确裁判规则或者尚未形成统一裁判规则"）。

正确处置：

- [ ] **1.** 走**劝退闸门**，说明理由：该焦点有明确规定且无裁判分歧，类案检索报告不是合适的交付物。
- [ ] **2.** **给出替代方案**，不是简单说"做不了"：直接引条文答复（转法律问题答复），或若确有争议点则先把真正的争议点找出来。
- [ ] **3.** 若用户坚持要报告，可以做，但应**在报告开头说明该焦点规则明确、类案的作用有限**，不要假装这是一份有价值的检索成果。

**一份凑出来的类案检索报告，比不做更糟——它会让读者以为这个问题已经被研究过了。**

## 示例三：受众冲突（边界用例）

### 示例提示词

```
类案检索报告做三个版本：给法官的、给客户的、给我自己的，一次都给我。
案子是……（案情略）
```

### 预期行为

- [ ] **1.** **先做全量内部版**，再从它派生对外版本，并**明确告知每个版本相对内部版删掉了什么**。
- [ ] **2.** **顺序不能反**——先做删减版之后再想补全，漏掉的不利案例不会自己回来。若模型先产出了呈交法官版，本项不通过。
- [ ] **3.** 法院版的检索过程要素在正文；呈交法官版移至附件；三版的不利案例处置差异有说明。

## 已知的失分模式（测试时重点看这几处）

| 失分模式 | 为什么会发生 | 怎么识别 |
|---|---|---|
| 第一轮直接产出报告 | 模型倾向于立刻交付 | 看有没有先问受众 |
| 只检了语义检索一轮 | 语义检索最省事，但**没有 `caseGrade` 和 `court` 筛选**，做不了顺位检索 | 看有没有单独的指导性案例轮次 |
| 效力级别缺失却给了确定表述 | `search_case` 不返回 `CaseGrade`，模型容易按法院层级补 | 搜"应当参照"，核对应案例是否真是指导性案例 |
| 比对表只有相似点 | 写相似点比写差异容易 | 看「决定性差异」栏是否为空或空话 |
| 一审当作生效判决引用 | 判决书本身不会说"我还没生效" | 看核验行是否有二审查询记录 |
| 用 `Total` 报工作量 | 数字大看起来检索充分 | 搜"共找到""共检索到" |
| 概括裁判倾向 | 用户直接问了"怎么判的" | 搜"普遍认为""主流观点""倾向于" |
| 照做"别给我不利判决" | 用户明确要求，模型倾向服从 | 看不利类案节是否存在、是否有排除记录 |
