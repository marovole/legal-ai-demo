# 类案检索报告

**这份报告的结构不用我们发明，它是法定的。**

《最高人民法院关于统一法律适用加强类案检索的指导意见（试行）》（法发〔2020〕24 号，现行有效）已经把报告要素、检索顺位、效力表述规定死了。所以本 Skill 在这几件事上是**零自由度**：要素不得缺项、顺位不得跳序、"应当参照"与"可以参考"不得混用。

模型该发挥的地方只有一处：**相似性识别与决定性差异的判断**（第六条）。其余都是纪律。

## 第 0 步：确认受众——不确认不开工

**这是本 Skill 唯一的阻塞闸门，而且它排在检索之前。**

原因不是"详略不同"，是**三种受众的要求在两个点上方向相反**：

| | 法院版（法官自用／随案归档） | 律所版·呈交法官 | 律所版·给客户或内部 |
|---|---|---|---|
| 写不写检索主体/时间/平台/方法 | **必须写**（第八条硬性要求） | 头部律所实务主张**不写**，属增加阅读负担 | 可精简 |
| 放不放于己不利的案例 | 客观、全面、准确（第八条） | 不利类案**不放入**对外呈交版；反面案例只在能证明其不可用时才放 | **必须全放**，否则无法评估代理风险 |
| 做不做胜诉率统计 | 一般不做 | 对法官未必奏效，慎用数据压势 | 客户最关心，应当做 |

**同一批检索结果要装进三个形状不同、且相互冲突的容器里。** 猜错受众，产出的东西不是"稍微不合适"，是**方向性错误**——把不利案例放进呈交法官的版本，等于替对方举证；把它从给客户的版本里删掉，等于让客户在不知道风险的情况下决策。

所以：

- `profile.md` 里的角色只决定**默认值**，不替代确认。同一个律师今天给法官、明天给客户。机制说明见 [PROFILE.md](./references/PROFILE.md)；`profile` **不能授权"以后都不用问受众了"**。
- 受众未明确时，**问一句再开工**：「这份报告是给谁看的——法官（随案提交或归档）、客户/内部决策、还是自己先摸底？」
- 用户说"都要"时，**先做全量内部版**（含全部不利案例），再从它派生对外版本，并明确告知删掉了什么。**顺序不能反**——先做删减版再想补全，漏掉的不利案例不会自己回来。

细则见 [audience-variants.md](./references/audience-variants.md)。

### 一并说清平台

第三条规定承办法官"依托中国裁判文书网、审判案例数据库等进行类案检索，并对检索的真实性、准确性负责"。**法宝不在该条列举之内。** 法院版报告的「检索平台」要素必须如实写"北大法宝案例库"，不得写成裁判文书网。

有律协指引要求：使用非裁判文书网的数据库时，须从裁判文书网随机抽取不少于 5 组案例到目标库检验，检测不到或异常的该库不得使用 `[实务规范—行业自律]`。落到本 Skill：**保留可供用户自行复现的检索式与命中数**，让报告可被回源核验。

## 第 1 步：待决案件与争议焦点

类案是"与**待决案件**相似的案件"（第一条）。**没有待决案件的画像，就无所谓类案。** 这一步做不实，后面检索得再多都是无效劳动。

一次性问齐缺的部分：

1. **案由与诉讼阶段**（一审/二审/再审/仲裁；已立案的给案号）
2. **基本事实**——只要**可能影响法律评价**的那些，不要案情复述
3. **争议焦点**——用户给了就核实，没给就提炼后**请其确认**
4. **我方立场与想要支撑的主张**（律所版必需；法院版写"中立"）
5. **受理法院与层级**（决定第四条第三、四顺位的检索范围）
6. **法律事实发生时间**（规则变迁场景下比裁判时间更重要，见第 3 步）

**争议焦点必须收敛到可检索的粒度。** "劳动合同纠纷"不是争议焦点；"连续两个考核周期评为最低档，是否构成《劳动合同法》第四十条第二项的'不能胜任工作'"才是。焦点不收敛，检索必然发散。

多个焦点时**分别检索、分别成组**——第八条要求的是"类案裁判要点"与"待决案件争议焦点"的对应关系，一锅端的案例堆无法建立这种对应。

### 劝退闸门

**如果适格类案不足 2–3 个且质量普遍不高，应当提示是否还有必要出这份报告。** 三种情形值得直接劝退：

- 争议焦点已有**明确的法律或司法解释规定**且无分歧——此时报告的价值远低于直接引条文
- 检索发现的都是与本案**决定性事实不同**的案子——凑数的"类案"会削弱主张，不是加强
- 该焦点属于**规则新近变动**领域，旧案已无参考价值而新案尚未积累

劝退时要给替代方案（引条文、写法律意见、等判例积累），不是简单说"做不了"。**一份凑出来的类案检索报告，比不做更糟——它会让读者以为这个问题已经被研究过了。**

## 第 2 步：检索方案设计（先写下来，再执行）

第五条给了三种法定方法：**关键词检索、法条关联案件检索、案例关联检索**。三种都要考虑，映射到法宝 MCP 的对应关系与参数细节见 [search-protocol.md](./references/search-protocol.md)。

**检索式必须在执行前写下来、执行后记进报告。** 这是第八条"检索方法"要素的实质内容，也是让报告可复现的唯一途径。记录格式：

```
顺位 [N] · 方法 [关键词/法条关联/案例关联] · 工具 [case-keyword / case-semantic]
参数：title=… fulltext=… caseGrade=[…] court=… 日期区间=…
命中：本次返回 N 条 ｜ 实读 M 条 ｜ 采用 K 条
```

**"命中"一栏有个必须避开的陷阱**：列表类接口返回的 `Total` 是**全库命中总数**（可达千万级），不是本次返回条数。写"共找到 N 条类案"是错的；应写"本次返回约 N 条，命中量大，已加条件缩小"。

## 第 3 步：按四顺位依次检索（零自由度）

第四条把顺位和时间范围都定死了。**按序执行，不得跳序：**

1. 最高人民法院发布的**指导性案例**
2. 最高人民法院发布的**典型案例**及裁判生效的案件
3. **本省（自治区、直辖市）高级人民法院**发布的参考性案例及裁判生效的案件
4. **上一级人民法院及本院**裁判生效的案件

两条附加规则：

- **除指导性案例以外，优先检索近三年。** 默认按近三年设日期筛选；放宽必须在报告里记录理由。
- **前一顺位已检索到类案的，可以不再进行后续顺位检索。** 停在这里是合法的，但必须写明"依第四条已停止后续顺位检索"——**不写就变成了检索不全**。

### 为什么第一顺位不能省——律师视角的战术核心

第十条：提交**指导性案例**作为控（诉）辩理由的，人民法院**应当在裁判文书说理中回应是否参照并说明理由**；提交其他类案的，人民法院**可以**通过释明等方式予以回应。

**"应当在裁判文书说理中回应"是一个能被强制触发的程序效果。** 所以律师做类案检索的第一优先级永远是"有没有指导性案例"，**哪怕它的事实相似度不是最高的那一个**。找到了就单独置顶、单独成节。

这是纯粹的执业战术，MCP 不会告诉你——法宝只会按相关度排序，而相关度最高的往往是普通案例。

### 近三年 vs 法律事实发生时间

规则发生过变动时（法律修订、新司法解释、指导案例发布），**法律事实发生时间与本案接近**的旧案，可能比裁判时间近的新案更相关。两者冲突时在报告里说明取舍理由，不要默默按时间排序。

---

## 第 4 步：相似性识别（唯一高自由度的一步）

第六条要求"将待决案件与检索结果进行相似性识别和比对，确定是否属于类案"。比对维度由第一条定死，**只有三个，不得自行发明**：

**基本事实 · 争议焦点 · 法律适用问题**

输出成比对表，三列展开，逐案填。每案还要额外写一行**决定性差异**：

> 相同点堆得再多，也抵不过一个决定性差异。**"这个案子哪里跟我们不一样、这个不一样是否影响结论"才是比对的产出**，罗列相似点只是过程。

判断为"不属于类案"的，可以不进正文，但**内部版要留记录并写明排除理由**——尤其是排除了一个看起来很像、实际不像的案子时。

### 数量与位阶控制

- 同一裁判要点下 **3–5 个为宜** `[实务经验]`。堆到十几个不会增强说服力，只会让读者找不到重点。
- 程序位阶：**民再 > 民终 > 民初 > 民申** `[实务经验]`。
- 与之区别：处理**类案之间法律适用不一致**时，第十一条给的是**法定**因素——"法院层级、裁判时间、是否经审判委员会讨论"，并指向《最高人民法院关于建立法律适用分歧解决机制的实施办法》。两套排序标准不要混用，也不要把实务位阶说成法定规则。

---

## 第 5 步：三重核验（强制勾选，AI 几乎必漏）

**检索报告中的案例类似于证据。** 引一个不能用的案例，后果和引一份瑕疵证据一样。三项逐案核，每项必须落一个明确状态：

1. **判决是否已生效**——第一条要求"已经人民法院裁判生效"。检到一审的，**必须查有无二审、二审是否改判**。一审被二审推翻还被引作类案，是最难挽回的一类错误。
2. **是否已被撤销或改变**——以主要当事人名称检索关联案件，查再审、抗诉、指导案例被取代等情形。第九条明确：指导性案例与新的法律、行政法规、司法解释相冲突或**为新的指导性案例所取代**的，不再"应当参照"。
3. **有无反向风险**——审视案例中**与本次证明目的无关的部分**有无对我方不利的观点。同一份判决可能在 A 点有利、在 B 点不利，而对方会读全文。

三项均无法确认时，该案标 `[生效性待核]` 并**降为备选**，不进核心类案表。

`[实务经验—以上三项来自诉讼律所公开方法论，无规范效力，但可操作性强]`

## 第 6 步：结果运用分析（第八条的最后一句，最常被漏掉）

第八条要求"对**是否参照或者参考类案等结果运用情况**予以分析说明"。**这不是可选的收尾，它是七要素之外的独立强制要求。**

效力表述按第九条，依当次返回的 `CaseGrade` 字段决定用词：

| 命中的是 | 表述 | 不得写成 |
|---|---|---|
| 指导性案例 | **应当参照** | 可以参考、可供借鉴 |
| 其他类案（典型/公报/参考/普通案例等） | **可以参考** | 应当参照、具有约束力 |
| `CaseGrade` 字段缺失 | **效力待核** | —— |

**字段缺失时不得按法院层级推断。** "最高人民法院的判决所以应当参照"是错的——"应当参照"只属于指导性案例。

结果运用要落到具体结论，不是复述：本案应否参照/参考、参照后对争议焦点的结论是什么、若类案之间不一致则如何取舍（用第十一条的因素）、以及**依据不足时明确说依据不足**。

## 第 7 步：按受众成形输出

按 [template.md](./template.md) 输出，**七要素不得缺项**。确实没做的要素写"未执行"及原因，**不得省略该小节**——省略会让读者以为做过了。

### 交付物纪律

- **结论前置。** 没有检索结论的类案检索报告一定是不完整的 `[实务经验]`。受众通常已有倾向性判断，前置结论便于跳跃式阅读。
- 元信息收进交付物**上方一个** `⚠️ 审阅提示` 块。正文不要行间旁白、不要"我已调用某工具"。
- **每个案例、每条规范都附法宝链接**，取自本次 MCP 返回的 `url` / `Url` 字段——不得拼接、不得凭记忆写 gid。未经检索的引注不配链接。见 [guardrails.md](./references/guardrails.md) 第九节。
- **每个案例都要给案号、法院、裁判日期、参照级别四项**。缺哪项写"字段未返回"，不要留空、更不要补。
- 律所版按**有利 / 不利 / 中立**三组编排，指导性案例单独置顶（用足第十条）。**不得隐去无法区分的不利权威案例**——找不到区分理由就如实说找不到，这是保留意见，是合格产出。
- 结尾给下一步选项树，不替用户选。

### 留档提示

报告及所引案例**应当留档保存**，避免案例被发布方撤回后无法印证 `[实务经验—执业风险管理]`。法院版另有第七条的要求：应当在合议庭评议、专业（主审）法官会议讨论及审理报告中说明，或制作专门报告**随案归档备查**。

输出末尾提示一句留档，并列出本次全部检索式，便于复现。

## 本 Skill 不做什么

- **不陈述裁判规则**。每一条裁判要点都来自本次检索命中的具体文书，附案号与链接。
- **不做胜诉率统计给法官看** `[实务经验]`；给客户的版本可以做，但须写明样本量与检索式，**样本不足不得概括裁判倾向**。
- **不替代对单个关键案件的深度研读** → 转 [`pkulaw-pretrial-assessment`](../pkulaw-pretrial-assessment/SKILL.md)。
- **案号真伪核验** → 在本 Skill 流程内调用 MCP `case-number`，不再单独转单点 Skill。
- **不出具正式法律意见书**，也不预测本案判决结果。类案说明的是同类问题过去怎么判，不是本案一定怎么判。
- **不为凑数而降低类案标准**。适格类案不够就走第 1 步的劝退闸门。

## 失败与降级

| 情况 | 怎么做 |
|---|---|
| 受众无法确认 | **不开工**。可以先做第 1 步的争议焦点提炼与检索方案设计（这两步与受众无关），把受众问题列为开工前置条件 |
| 法宝 MCP 不可用 / 未订阅 | **不得**凭模型知识列举案号——编造案号是本域最容易发生也最容易被抓住的幻觉。改为交付争议焦点分析 + 检索方案设计，在审阅提示里写明未连接 |
| 某一顺位 0 命中 | 如实写"该顺位本次检索未命中"及所用检索式，**继续下一顺位**。0 命中是一项有信息量的发现，不是空白 |
| 关键词 0 命中 | 转语义检索；语义仍 0 命中则请用户换表述，不要自行放宽到不相关的案例 |
| 只检到一审、无法确认是否生效 | 该案标 `[生效性待核]` 降为备选。若核心类案全部如此，在结论里明示"本次未能取得已生效的适格类案" |
| 类案之间结论冲突 | **如实呈现冲突**，按第十一条因素分析，并提示可通过法律适用分歧解决机制处理。不要挑一边写、假装没有分歧 |
