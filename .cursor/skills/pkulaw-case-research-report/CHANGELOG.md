# CHANGELOG

## 1.0.0 — 2026-07-29

首个版本。重写 `pkulaw-mcp-case-memo`，按整改方案第八节落地。

### 法定结构

- 全文核实《最高人民法院关于统一法律适用加强类案检索的指导意见（试行）》（法发〔2020〕24 号）**第一至十二条**，经北大法宝 `get_article` 逐条取回原文，时效性均为「现行有效」，链接 `https://pkulaw.com/chl/0749b01d6f2da00dbdfb.html`。写入 `references/statutory-structure.md`，**逐字未转述**。
- 第八条七要素 + 结果运用分析共八项落为模板的必填小节，缺项不得省略。
- 第四条四顺位落为按序执行的检索算法，含"近三年"默认筛选与"前顺位命中可停但须记录"规则。
- 第九条效力表述落为依 `CaseGrade` 字段判定的对照表，禁止按法院层级推断。

### 核验中的两点新发现（整改方案原稿未覆盖）

- **第十一条**规定处理类案法律适用不一致的**法定**权衡因素为"法院层级、裁判时间、是否经审判委员会讨论"，并指向法律适用分歧解决机制。此前方案只写了实务界的"民再 > 民终 > 民初 > 民申"位阶——两者效力不同、用途不同，已在 `similarity-and-screening.md` 分表列出并禁止混用。
- **第三条**列举的检索平台为"中国裁判文书网、审判案例数据库"，**不含北大法宝**，且该条明确检索者对检索的真实性、准确性负责。故法院版报告的「检索平台」要素必须据实披露为法宝案例库。律协关于"换库须交叉验证"的指引在此找到规范落点，落为"保留可复现检索式"的要求。

### 三个特有机制

- **受众阻塞闸门（第 0 步）**：法院版／呈交法官版／内部版在"写不写检索过程要素"和"放不放不利案例"两点上要求相反，受众未确认不开工。用户说"都要"时强制先做全量内部版再派生，顺序不可反。
- **指导性案例单独检索一轮**：依第十条，提交指导性案例能强制法院在裁判文书说理中回应，故其优先级高于事实相似度；该轮不设近三年筛选（第四条）。未命中也保留小节并写明检索式。
- **劝退闸门**：适格类案不足 2–3 个、规则已明确、或规则新近变动时，主动说明不必做并给替代方案。

### MCP 落地（`search-protocol.md`）

- 据本次 `tools/list` 实测，明确 `case-keyword` 与 `case-semantic` **能力不对称**：`search_case` 无 `caseGrade`／`court` 筛选，返回值亦不含 `CaseGrade`。由此定两条硬规则——四顺位筛选必须走 `case-keyword`；语义检索命中的案子须回补效力字段，回补失败只能写「效力待核」。
- 如实记录**两处能力缺口**：法宝 MCP 无"法条关联案件检索"与"案例关联检索"的专用接口（第五条法定方法），给出近似做法及其局限，并要求在报告中披露用的是近似手段。
- 记录 schema drift 的两组参数名（`province`／`courthouse_province` 等）及三级处置顺序：按当次广告名 → 换另一组 → 去掉筛选并入检索文本，不放弃检索。
- 记录实测异常：`get_article` 偶发返回全空字段（本次第九条首调即为全空，重试正常），**返回全空不等于该条不存在**；标题用半角括号更稳。

### 引注纪律

- `references/guardrails.md` 改为由 `scripts/build-guardrails.ps1` 从 `docs/GUARDRAILS.md`（整仓 canon）生成，本 Skill 只维护 `guardrails-appendix.md`。
