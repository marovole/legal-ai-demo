# 执业档案机制（本 Skill 内嵌副本）

> **此文件由 `scripts/build-guardrails.ps1` 从 `docs/PROFILE.md` 复制，供本目录单独导入时使用。**  
> 修改机制 → 改仓级真源后重跑脚本。  
> **用户自己的配置**仍放在工作区根目录 `profile.md`，不要改本副本当配置用。

---
> **一句话**：同一个法律问题，法官、律师、企业法务、非法律专业人员需要的是**四种不同的交付物**。`profile.md` 让用户配一次，所有 Skill 都按它调整输出。

本文说明机制与字段；空白模板：整仓见根目录 [`profile.example.md`](./profile.example.md)；单独导入 Skill 时见同目录 `profile.example.md`。

> **单独导入**：各交付型 Skill 的 `references/PROFILE.md` 与 `references/profile.example.md` 由 `scripts/build-guardrails.ps1` 从本文与根目录模板同步。改机制请改仓级真源后重跑脚本。

---

## 一、放在哪、怎么被读到

`profile.md` 是**用户自己的配置文件，不是本仓库分发的内容**。约定：

| 使用方式 | 放置位置 |
|---|---|
| 在 IDE／CLI 里用（Cursor、Claude Code 等） | 工作区根目录 `profile.md`，或 `.cursor/profile.md` |
| 通过 MCP 门户挂载 Skill | 会话开始时粘贴一次，或由平台注入 |

Skill 侧的读取纪律统一为：**「读 `profile.md`（如已配置）」**。

**它是可选的。** 所有 Skill 在未配置时都必须能正常工作——见第四节的降级规则。**不得因为缺少 profile 就拒绝执行。**

## 二、字段

只有 `角色` 是必填的，其余缺省即按第四节降级。

```markdown
# 执业档案

- **角色**：律师 / 企业法务 / HR / 法官·法官助理 / 非法律专业人员
- **机构**：[所在律所、公司或法院；用于交付物抬头]
- **执业辖区**：[常办案件的省市，如「上海」「广东·深圳」；用于地方规则检索的默认值]
- **常办领域**：[如 劳动人事、公司与投资、合同与交易、争议解决]
- **默认交付受众**：[给自己 / 给业务或客户 / 给法官 / 对外正式出具]
- **文书风格**：[简洁要点式 / 完整论证式]；称谓：[我方·对方 / 甲方·乙方 / 委托人·相对方]
- **语言与计量**：[简体中文；金额单位：元／万元]
```

### 各字段实际改变什么

| 字段 | 影响 |
|---|---|
| **角色** | 交付物抬头与定性；**后果性动作闸门是否触发**（见第三节）；默认受众 |
| 执业辖区 | 地方规则检索的默认地域。**不替代确认**——用工地、履行地、受理法院可能都不在常办辖区 |
| 常办领域 | 影响术语密度与解释量：常办领域内可用行话，领域外应多解释一句 |
| 默认交付受众 | 类案检索报告的受众默认值。**仍须每次确认**，因为同一个律师今天给法官、明天给客户 |
| 文书风格 | 段落长度、是否展开论证、称谓统一 |

## 三、硬边界：配置不能关掉安全闸门

**这是本机制最重要的一条。**

`profile.md` 只能调整**表达方式与默认值**，**不能**用来：

- 关闭任何红线扫描或要件检查
- 跳过后果性动作闸门
- 降低引注与溯源纪律（`docs/GUARDRAILS.md` 对所有角色一律适用）
- 把 `[待核]` / `[待判]` 标签抑制掉
- 授权"以后都不用问受众了"

**理由**：这些机制存在的目的正是防止在压力下走捷径，而"配置里说不用做"恰恰是最典型的走捷径路径。一个能被配置关掉的闸门不是闸门。

**角色只能让闸门更严，不能更松。** 例如「非法律专业人员」会**额外**触发劳动解除审查的简报闸门；但「律师」不会让红线扫描变成可选。

## 四、未配置时的降级

未检测到 `profile.md` 时：

1. **按最保守的角色处理**：`企业法务`（比"律师"保守、比"非法律专业人员"少一道强制简报）。
2. 在审阅提示块里标 `[临时—未配置执业档案]`。
3. **不要为了拿到 profile 而中断任务**。可以在交付物末尾用一行提示：「配置 `profile.md`（角色、辖区、常办领域）后，输出可按你的实际身份与辖区定制。」
4. 辖区未知时，地方规则部分写「辖区未确认，未检索地方规则」并列为首要待补事实——**不要按最常见的地区猜**。

## 五、四种角色的交付物差异

| | 法官·法官助理 | 律师 | 企业法务 / HR | 非法律专业人员 |
|---|---|---|---|---|
| 交付物定性 | 可归档备查的中立文书 | 工作底稿或对外文书草稿 | 能发给业务的口径 | 能拿去跟决策者讲清楚的说明 |
| 立场 | 中立 | 我方立场（须先确认代表哪一方） | 本方公司 | 本方 |
| 术语 | 可用全部专业术语 | 同 | 常用术语可直接用 | **法律概念首次出现要解释一句** |
| 过程披露 | **必须**（法发〔2020〕24 号第三、八条对类案检索有法定要求） | 视受众，通常收进附件 | 精简 | 精简，但结论的不确定性要讲清 |
| 后果性动作 | —— | 可直接给结论 | 可给结论，标注需复核 | **触发简报闸门**：不直接给"可推进"，改出具带给律师的简报 |
| 金额与数字 | 按需 | 按需 | **必须给数字区间**，形容词对决策无用 | 同，且要说明区间的假设 |

**「法官」角色有一处特殊性**：法发〔2020〕24 号第三条规定承办法官"对检索的真实性、准确性负责"。这是**法定义务**，所以该角色下的类案检索报告必须写全七要素并支持独立复核，不适用律所版"检索过程移入附件"的简化。

## 六、Skill 侧的写法约定

各 Skill 引用本机制时，统一写成（下面是**待抄的模板文本**，其中的相对路径按 `skills/<name>/SKILL.md` 的位置写）：

```markdown
读 `profile.md`（如已配置）确定用户角色。未配置时按「企业法务」处理，
并在审阅提示里标 `[临时—未配置执业档案]`。机制说明见 [PROFILE.md](./references/PROFILE.md)
（单独导入本 Skill 时用此路径；整仓开发亦可对照 `docs/PROFILE.md`）。
```

**不要在 Skill 里重复本文的字段表**——重复就会漂移。只写"读它"和"这个 Skill 用它的哪个字段做什么"。

**用户配置文件**仍放在工作区根目录 `profile.md`（或 `.cursor/profile.md`），**不是** `references/` 里的副本。`references/profile.example.md` 只是可复制的空白模板。
