# 受众变体：三种形状，两点相反

```
最后核验日期：2026-07-29
核验对照来源：法发〔2020〕24 号第三、七、八条（法宝逐条取回）+ 头部律所公开方法论
新鲜度窗口：12 个月
过期处置：标 [实务经验] 的内容窗口过期后降级为 [模型知识—待核]
```

> 本文对应 SKILL.md 的第 0 步（阻塞闸门）与第 7 步（成形输出）。
>
> **这份 reference 存在的理由**：如果三种受众只是详略不同，就不需要一个阻塞闸门，写完再裁剪即可。但它们在两个点上要求**方向相反**，裁剪解决不了。

## 一、三种受众的差异总表

| | **法院版**<br>法官自用／随案归档 | **律所版·呈交法官** | **律所版·给客户或内部** |
|---|---|---|---|
| 规范依据 | 第三、七、八条（**硬性**） | 无规范约束，实务惯例 | 无规范约束 |
| 立场 | **中立** | 我方立场 | 中立评估我方处境 |
| 检索主体/时间/平台/方法 | **必须写全**（第八条） | **实务主张不写** `[实务经验]` | 可精简，但检索式建议保留 |
| 不利案例 | **客观、全面、准确**（第八条） | **不放入**；反面案例只在能证明其不可用时才放 `[实务经验]` | **必须全放** |
| 胜诉率统计 | 一般不做 | **慎用**，对法官未必奏效 `[实务经验]` | **应当做**，客户最关心 |
| 指导性案例处理 | 按第九条判断是否参照 | **单独置顶**，用足第十条 | 置顶，并说明其程序价值 |
| 结论 | 是否参照及理由 | 我方主张应被支持的论证 | 胜败风险区间与建议 |
| 归档 | **随案归档备查**（第七条） | 报告及附件留档 `[实务经验]` | 留档 |

---

## 二、两个相反点，逐个说清

### 相反点 1：检索过程要素写不写

**法院版必须写。** 第八条把检索主体、时间、平台、方法、结果列为报告应当包括的内容；第七条要求随案归档备查——**归档件要能被后来人独立复核**，没有检索过程就无法复核。第三条更明确规定检索者"对检索的真实性、准确性负责"。

**律所版呈交法官时，头部律所实务主张不写** `[实务经验]`。理由是法官的阅读时间稀缺，检索过程对他的决策无用——他要的是"哪几个案子、法院怎么判、为什么可比"。把四段检索过程放在前面，等于让最有价值的内容后移。

**所以这不是"要不要偷懒"的问题**：同一段内容，在法院版里是合规要素，在呈交法官的律所版里是干扰项。

**处置**：律所版呈交法官时，把检索过程要素移到**附件**或末尾，正文不占位置。这样既不增加阅读负担，又保留了可复现性（对方或法院要求时可出示）。**不建议彻底删除**——那份检索式记录是我方尽职的证据。

### 相反点 2：不利案例放不放

这一点风险最高，两个方向的错误后果都很严重：

| 错误 | 后果 |
|---|---|
| 把不利案例放进**呈交法官**的版本 | 等于替对方举证。法官会看到我方自己承认存在相反判决 |
| 把不利案例从**给客户**的版本里删掉 | 客户在不知道风险的情况下决策。这直接关系代理风险评估与执业责任 |

**法院版没有这个问题**：第八条要求"客观、全面、准确"，法官版必须两面都放。

**律所版呈交法官时的正确做法不是"隐去"，是"区分"** `[实务经验]`：

- 能论证不利案例**与本案有决定性差异**的 → 主动放上去并给出区分理由。主动区分比等对方提出更有力。
- **无法区分的不利权威案例** → **不得隐去**。找不到区分理由就如实告知承办人"这个案子我们区分不掉"，由承办人决定策略（调整主张、寻求和解、或准备正面回应）。这是保留意见，是合格产出。

> **这条底线要划清楚**：不放不等于可以假装不存在。**报告的内部版必须完整，对外版本的删减必须让承办人知道删了什么。** 一份让承办人误以为"没有不利判例"的报告，比一份说"有三个不利判例，两个能区分、一个不能"的报告危险得多。

## 三、"都要"怎么处理：顺序不能反

用户说"三个版本都给我"时：

1. **先做全量内部版**——含全部命中、全部不利案例、全部排除记录与排除理由。
2. **再从它派生对外版本**，并**明确告知每个版本相对内部版删掉了什么**。

**顺序不能反。** 先做删减版、之后想补全，漏掉的不利案例不会自己回来——因为你已经不记得当初为什么没检到它了。同理，排除某个案子的理由必须在排除**当时**写下来。

---

## 四、`profile.md` 只定默认值，不替代确认

角色档案能给出一个合理默认，但**不能替代每次确认**：

| profile 角色 | 默认受众 | 为什么仍要问 |
|---|---|---|
| 律师 | 律所版·内部 | 同一个律师今天给法官、明天给客户 |
| 企业法务 | 律所版·给客户/内部 | 也可能在准备提交给法院的材料 |
| 法官/法官助理 | 法院版 | —— |
| 非法律专业人员 | 律所版·给客户 | 且须加"本文为工作稿，须律师复核"的定性 |

**确认话术**（一句话，不要问成问卷）：

> 这份报告是给谁看的——法官（随案提交或归档）、客户/内部决策、还是自己先摸底？三种版本在"要不要写检索过程"和"要不要放不利案例"上要求相反，所以先确认一下。

**把理由一起说出来**，用户才知道这不是流程性提问。未答复前可以先做第 1 步（争议焦点提炼）和第 2 步（检索方案设计）——这两步与受众无关。

## 五、各版本的编排骨架

### 法院版

七要素**全部在正文**，按第八条顺序。中立表述，不分有利不利，按裁判观点分组（多数观点／少数观点／存在分歧）。结论落在"是否参照及理由"。末尾注明随案归档。

### 律所版·呈交法官

```
一、结论（前置）
二、指导性案例（若有，单独置顶 —— 用足第十条）
三、类案裁判要点与本案比对
四、结论运用
附件：待决案件争议焦点 · 检索主体/时间/平台/方法/结果 · 完整检索式
```

**结论必须前置** `[实务经验]`——"没有检索结论的类案检索报告一定是不完整的"。受众通常已有倾向性判断，前置结论便于跳跃式阅读。

### 律所版·给客户或内部

```
一、结论与风险区间（前置）
二、待决案件争议焦点
三、有利类案 ｜ 四、不利类案 ｜ 五、中立/存在分歧
六、样本情况与裁判倾向（样本不足时明示不足，不得概括倾向）
七、对方可能如何使用不利类案（反向自查）
八、结论运用与建议
附：检索式记录 · 排除案例及排除理由 · 三重核验状态
```

**第七节是内部版独有的**，也是最容易被跳过、但对代理策略最有用的一节。做法见 [similarity-and-screening.md](./similarity-and-screening.md) 第二节的反向自查。
