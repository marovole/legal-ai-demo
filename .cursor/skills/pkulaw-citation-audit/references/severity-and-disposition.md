| 字段 | 值 |
|---|---|
| 最后核验日期 | 2026-07-29 |
| 核验对照来源 | 方法论／流程脚手架；不含可直接写入交付物的实体法结论 |
| 新鲜度窗口 | 180 日 |
| 过期处置 | 过期后本文件内容降为 `[模型知识—待核]`，不得当作已核依据；仅可作检索起点与流程脚手架 |

---

## 分级轴：这处错误动不动摇结论

**不按错误的技术类型分级，按"改了之后结论要不要重写"分级。**

这是本 Skill 与旧版核验最重要的差别。旧版的三态（通过／待复核／需修正）量的是"引注与工具返回是否一致"，也就是技术一致性。但签发人真正要知道的是：**我现在能不能发**。

同一个"需修正"，可能是把《民法典》改成《中华人民共和国民法典》（五分钟），也可能是发现整份意见书的核心结论没有依据（重写）。把这两件事放进同一格，等于没有分级。

---

## 四级

### 🔴 动摇结论——不得签发

改掉这处之后，**结论本身要重写**。

| 情形 | 为什么是 🔴 |
|---|---|
| 所引规范已废止，**且现行规则与之相反** | 结论建立在已经不存在的规则上 |
| **命题对应性不成立**（维度 6）——该法条实际管的不是这件事 | 结论没有依据 |
| 关键结论的依据是**编造的**法规名称或条号 | 同上，且性质更严重 |
| 引用了条文的前半句，**省略的但书改变了规则含义** | 结论方向可能相反 |
| 所引**案例已被改判或再审撤销** | 引一个被推翻的判决，比不引更糟 |
| 「可以」被写成「应当」，且结论依赖这个强度 | 结论强度无依据 |
| 只引支持己方的规范，**遗漏了方向相反的现行规定** | 对方或监管必然引出来 |
| 地方口径被写成全国规则，**且结论依赖其普遍适用性** | 换个地区结论不成立 |
| **`部分失效` 的文件，所引条文正在失效范围内** | 依据已不存在 |

**处置**：不得签发。写清**动摇了哪一句结论**，并指出缺口是什么（缺依据／依据相反／依据射程不够）。**指出缺口即可，不要顺手把实体分析重做一遍**——那是别的 Skill 的活。

### 🟠 须修正后签发

引注有实质瑕疵，但**结论方向不变**。

- 条号错误（现行规则内容一致）
- 应改引现行版本，但**新旧规则实质相同**
- `部分失效` 文件未核，经核所引条文不在失效范围内 → 补注即可
- 指导性案例被当作裁判依据引用 → 改为裁判理由引述
- 部门规章／地方文件／会议纪要被写成硬依据 → 降级表述
- 法规名称不完整、缺文号
- 引述与原文有差异但不改变含义
- 结论有绝对化表述（「必定」「不存在任何风险」）→ 改写

**处置**：逐条给出**具体改法**，不是"建议核实"。改完可发。

### 🟡 建议修正

形式与规范性问题，**不阻塞签发**。

- 并列引用顺序不符法释〔2009〕14 号第二条
- 引用不整条（且省略部分不影响含义）
- 缺法宝链接
- 指导性案例未注明编号
- 案例引注缺审级或裁判日期
- 简称使用

**处置**：列入清单，交由签发人决定是否本次处理。

### ⬜ 无法核验

- 本次未检索到该规范
- MCP 不可用、未订阅、积分用尽
- 时间锚定不明（法律事实发生时间未知）
- 工具返回"需复核"且未能人工确认
- 文稿未提交该段落
- **无源命题**（「根据相关法律规定」这类无出处表述）

**处置**：**明确标注为未核，不得折算为通过。**

> **一份有 5 处 ⬜ 的底稿，签发结论不能是"可以签发"。**
> 应写成：「修正后可签发；另有 5 处无法核验（清单见第 X 节），签发人须自行判断是否承担该风险。」

## 签发结论三态

写在底稿**最前面**，不放在结尾。

| 结论 | 条件 |
|---|---|
| `可以签发` | 无 🔴；🟠 已全部给出改法；⬜ 项已列明且签发人已知悉 |
| `修正后可签发` | 无 🔴，但存在须改的 🟠 |
| `不得签发` | 存在 🔴 |

**三态都必须带核验范围限定**，例如：

> `修正后可签发`（**仅限已核范围：正文第 2、3、5 节及结论段。附件与脚注未提交，不在核验范围内。**）

**不得给出无范围限定的结论。** 这一条在用户催"来不及了你就说能不能发"时尤其要守住——那正是最容易出事的时刻。

## 时间不够时的核验顺位

两个被本 Skill 替代的旧卡片，示例提示词都是"今晚要发"。这是真实场景，所以顺位要明确。

**按下列顺序核，随时可以停下来交付已完成部分：**

1. **结论段的全部引注**——结论段之外的引注出错，通常只是瑕疵；结论段出错才动摇结论。
2. **🔴 候选的快筛**：把所有引注的法规名跑一遍 `get_law_list`，只看 `timeliness`。**这一步很快，且能一次捞出最危险的一类**（引了已废止规范）。
3. **无源命题**——不需要检索，只需要读，成本极低而风险极高。
4. **维度 6 命题对应性**，只做结论段。这一步慢但价值最高。
5. **条号逐条核**（维度 3）。
6. 其余维度。
7. 🟡 类格式问题——**时间不够时直接跳过**，在底稿里写明"本次未核格式项"。

**交付时必须写明停在了第几步**，例如：

> 本次按顺位完成第 1–4 步。第 5 步（条号逐条核）仅完成结论段，正文第 4 节的 7 处条号未核，已标 ⬜。

## 处置写法

每条 🔴 和 🟠 都要给出可直接执行的动作，**三个字段**：

```
#7 🔴 动摇结论
原文：「根据《中华人民共和国合同法》第一百二十二条，我方有权选择要求对方
       承担侵权责任。」
问题：《合同法》已随民法典施行废止。经核本案法律事实发生于 2023 年 5 月
       （合同签订日），应适用民法典；竞合选择权现由民法典第一百八十六条
       承载。此外，第 3 节结论「故我方可主张精神损害赔偿」依赖侵权路径成立，
       该结论的依据链因此断裂。
改法：改引《中华人民共和国民法典》第一百八十六条〔附链接〕；第 3 节结论
       须重新核对——民法典第一百八十六条的表述为「受损害方有权选择」，
       与原引述强度一致，但精神损害赔偿的依据须另行补充，本处未提供。
```

三条纪律：

- **「问题」必须说清动摇了哪一句结论**，而不只是"该引注有误"。
- **「改法」必须具体到可以直接替换的文本**，「建议核实」不是改法。
- **改法之外的缺口要如实说"本处未提供"**，不要为了让底稿看起来完整而顺手补一个未经检索的依据。

---

## 两句必须出现在底稿里的话

- **「通过」只表示与本次 MCP 返回一致，不等于已完成法律审查。**
- **本底稿不替代承办人的实体判断与签发责任。**

这两句是旧版写对的部分，保留。核验层最容易造成的错觉就是"过了核验就没事了"——而维度 6 之外的八个维度全绿，文稿依然可能整段无依据。
