# pkulaw-citation-audit · 文稿签发前核验

文稿对外发出或签发之前，把里面的法规与案例引注核成一份可复核的底稿，并给出**能不能发**的结论。

## 它替代了哪两个 Skill

本 Skill 合并重写了 `pkulaw-mcp-opinion-citation-check`（意见书签发前核验）与 `pkulaw-mcp-regulatory-reply-check`（监管回复依据核查）。

**这两个卡片是近乎重复的。** 它们的示例提示词是：

> 意见书签发前核验：「这份法律意见书今晚要签发，帮我把里面引用的法条先核一遍，重点看结论部分。」
> 监管回复依据核查：「这份监管问询回复今晚要发，先帮我看一下里面引用的法规和条号有没有问题，重点看结论部分。」

同一个任务、同一个句式，只换了个名词，而且**两个都是 featured**——用户看到两张卡不知道该点哪个。流程也几乎逐步相同（锁定范围 → 识别引用 → 回源 → 一致性核验 → 出底稿），差别只是列了哪几个 MCP 工具。

**更要紧的是：这两条提示词里都没有待核的文稿。** 一个核验类 Skill，提示词只有一句"帮我核一下"，模型手上没有任何引注可核，于是输出一份空模板。这是结构性缺陷，不是标准新旧的问题。[examples.md](./examples.md) 的**示例四就是这条原始提示词**，作为回归测试保留——正确行为是拒绝空转。

## 核心改动：换掉分级轴

旧版的三态是 **通过 / 待复核 / 需修正**，映射到工具原生的 **命中 / 需复核 / 不命中**。

**这在量"引注与工具返回是否一致"，也就是技术一致性。** 但签发人真正要知道的是"我现在能不能发"。同一个"需修正"，可能是把《民法典》改成《中华人民共和国民法典》（五分钟），也可能是发现核心结论没有依据（整份重写）。放进同一格等于没有分级。

新的分级轴是：

> **改掉这处引注之后，结论还站得住吗？**

🔴 动摇结论（不得签发）／🟠 须修正后签发／🟡 建议修正／⬜ 无法核验。签发结论落三态：`可以签发` / `修正后可签发` / `不得签发`，**且必须带核验范围限定**。

保留了旧版写对的两句：「通过」只表示与本次返回一致、不等于已完成法律审查；本底稿不替代承办人签发责任。

## 五个特有机制

1. **阻塞闸门：没有文稿不开工。** 直接修掉旧版的空转。拿不到全文时明确告知"我只能核你给我的这部分"，并在底稿里写明未核范围。

2. **时间锚定排在时效性核验之前。** **引用已废止的法律不一定是错误**——依《民法典时间效力若干规定》第一条，民法典施行前的法律事实适用当时的法律。所以处理 2019 年合同争议的文稿引《合同法》是正确的，改成《民法典》才是错的。naive 核验器会把它误判为错误，这是本 Skill 与旧版最重要的差别之一。[examples.md](./examples.md) 主用例专门埋了一对反向桩来测这一点：同一部已废止法律，一处该改一处不该改。

3. **无源命题检测。** 「根据相关法律规定……」「依照有关司法解释……」这类表述**没有条号可核，所以任何引用核验工具都发现不了它们**——`citation-validator` 只能核你给它的条号，识别不出"这句话根本没给出处"。但它们和显性引注一样在支撑结论。处置是二选一：补出处，或把表述从"法律规定"降级为"我们的判断"。

4. **可引性核验。** 旧版完全没有这一维。哪些只能作为说理论据、指导性案例不得作为裁判依据引用、地方口径不能写成全国规则——这三类错误能通过条号与原文的全部检查。

5. **命题对应性单列一步。** 前面几维都在核"这条法条是不是这么写的"，这一步核"这么写的法条是不是支持了那句话"。**这是唯一无法自动化的维度，也是文稿真正出事的地方**：只引对己方有利的前半句、省略但书，能通过原文比对、条号核对、时效性核验的全部检查。

## 引注说明

本 Skill 引用的条文均于 **2026-07-29** 经北大法宝 MCP 逐条取回原文核对。骨架规范是：

**《最高人民法院关于裁判文书引用法律、法规等规范性法律文件的规定》（法释〔2009〕14 号，现行有效）**，七条已全部取回。它对本 Skill 的作用等同于法发〔2020〕24 号对类案检索报告的作用。三条最有用：

| 条 | 内容 | 落到核验 |
|---|---|---|
| 第一条 | 「应当准确完整写明规范性法律文件的名称、条款序号，需要引用具体条文的，**应当整条引用**」 | 名称完整性、条号必写、**整条引用**（省略但书是 🔴 的主要来源） |
| 第二条 | 并列引用顺序：法律及法律解释 → 行政法规 → 地方性法规 → 自治条例或单行条例 → **司法解释**；先基本法律后其他法律；先实体法后程序法 | 顺序核验（🟡）。**注意司法解释排最后**，与很多人的习惯相反 |
| 第六条 | 第三、四、五条之外的规范性文件，经审查认定为合法有效的，**可以作为裁判说理的依据** | **裁判依据 vs 说理依据的区分**，是可引性核验的总判据 |

另外整理出完整的**案例效力阶梯**（四类，效力完全不同，但文稿里常一律写成"根据最高人民法院的案例"）：

| 类型 | 效力 | 依据 |
|---|---|---|
| 指导性案例 | **应当参照**；作为裁判理由引述，**不作为裁判依据引用**；须注明编号 | 法〔2015〕130 号第十、十一条；法〔2021〕289 号第九条 |
| **人民法院案例库入库案例** | 可作裁判考量、理由参引，不作裁判依据 | **法〔2024〕92 号第二十一条**（2024 年新制度，模型知识里可能没有） |
| 公报案例、参考性案例 | 尚不能直接作为参照适用，有参考价值 | 最高法答复（两高工作文件） |
| 普通裁判文书 | 无拘束力 | —— |

## 一处自指的诚实标注

本 Skill 引用了两份「最高人民法院对提案／建议的答复」（`effectiveness` 为"两高工作文件"）来支撑"指导性案例不是正式法律渊源""公报案例尚不能直接作为参照适用"这两个命题。

**按本 Skill 自己定的规则，这两份答复只能作为说理论据，不能作为硬依据。** 这一点已在 [`references/guardrails-appendix.md`](./references/guardrails-appendix.md) D 节如实标注，未做美化。同节还标注了《关于案例指导工作的规定》第七条（"应当参照"的原始出处）本次未直接取回原文，只在答复的转述中见到。

一个检查别人引注的 Skill，自己的引据必须先经得起同一套检查。

## 尚未验证

**本 Skill 未附 `sample-output`。** 产出物由使用者按 [examples.md](./examples.md) 实跑生成，再对照 24 项验收标准核。

主用例（法律意见书节录）埋了 11 个桩，其中**两个是反向桩**——看起来像错误但实际正确。重点观察 R1 与桩 1 这一对：同一部已废止的《合同法》，第六节引它是正确的（2019 年法律事实），第三节引它是 🔴（2023 年法律事实）。**把两处一律判为"已废止属错误引用"是最可能的失败方式**，也是 naive 核验器的典型行为。

示例四是回归测试，用的是被替代卡片的原始提示词，**正确行为是拒绝开工**。
