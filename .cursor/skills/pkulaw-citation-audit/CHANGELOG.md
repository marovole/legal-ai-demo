# 变更记录

## 1.0.0 — 2026-07-29

新增 Skill，合并重写 `pkulaw-mcp-opinion-citation-check` 与 `pkulaw-mcp-regulatory-reply-check`。两者原为近乎重复的 featured 卡片（同一流程、同一三态、同一句式的示例提示词，只换了文书类型的名词）。

### 修掉的结构性缺陷

1. **提示词里没有待核文稿** —— 两个旧卡片的示例提示词都只有一句"帮我核一遍"，模型手上没有引注可核，输出必然是空模板。新增第 0 步阻塞闸门：没有文稿或引注清单不开工。旧提示词作为**回归测试**保留于 `examples.md` 示例四。
2. **分级轴量的是技术一致性** —— 旧版三态（通过／待复核／需修正）映射工具原生态（命中／需复核／不命中），量"引注与返回是否一致"，不告诉签发人能不能发。新分级轴为**"改掉这处之后结论还站得住吗"**，四级 + 签发三态，且结论必须带核验范围限定。
3. **没有时间锚定** —— 旧版会把引用已废止法律一律判为错误。依《民法典时间效力若干规定》第一条，民法典施行前的法律事实适用当时的法律，故 2019 年争议引《合同法》是正确的。新增第 2 步，排在时效性核验之前。
4. **没有可引性维度** —— 旧版完全未覆盖"这类文件能不能当依据引"。新增以法释〔2009〕14 号为骨架的可引性核验。
5. **没有无源命题检测** —— 「根据相关法律规定」这类表述没有条号可核，任何引用核验工具都发现不了，但同样在支撑结论。新增独立抽取与处置。
6. **没有命题对应性核验** —— 旧版只核"这条法条是不是这么写的"，不核"这么写的法条是不是支持了那句话"。后者才是文稿出事的主因，且是唯一无法自动化的维度。独立为第 4 步。

### 保留

旧版写对的两句纪律：「通过」只表示与本次 MCP 返回一致、不等于已完成法律审查；本底稿不替代承办人的实体判断与签发责任。工具原生三态与本 Skill 判定的映射关系也保留在 `audit-dimensions.md` 维度 4。

### 结构

- 八步流程（0–7）：文稿闸门 → 抽取引注（含无源命题）→ 时间锚定 → 九维逐条核验 → 命题对应性 → 结论层核验 → 分级与签发处置 → 输出
- 三份领域 reference + 生成的 `guardrails.md` + 本域 `guardrails-appendix.md`
- 五个测试用例、24 项验收标准
- 含**时间不够时的核验顺位**（两个旧卡片的示例提示词都是"今晚要发"，这是真实场景）

### 规范核验（2026-07-29 经北大法宝 MCP 逐条取回）

- **法释〔2009〕14 号第一至七条**（全部取回，现行有效）——骨架规范
- 立法法（2023 修正）第九十九条（效力层级）
- 法释〔2020〕15 号（民法典时间效力）第一条
- 指导性案例规则：法〔2015〕130 号第十、十一条；法〔2021〕289 号第九条；法〔2021〕294 号第八项；法发〔2020〕24 号第十条
- 法〔2024〕92 号第二十一条（人民法院案例库入库案例）
- 法发〔2018〕10 号第十三条（说理论据白名单）
