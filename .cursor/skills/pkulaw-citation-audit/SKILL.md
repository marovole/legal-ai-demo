# 文稿签发前核验

**一份法律文稿出事，很少是因为条号打错了一位数，通常是因为引的那条法根本不支持写出来的那句话。**

所以本 Skill 的分级轴不是"错误的技术类型"，而是：

> **改掉这处引注之后，结论还站得住吗？**

条号错了一位、法规名称写了简称、并列引用顺序不对——这些是文字工作，改完文稿照发。而"所引法条已废止且现行规则相反""这条法条其实不支持这个结论""关键结论的依据是编出来的"——这些意味着**整段甚至整份要重写**。两类东西在旧版核验里都叫"需修正"，这是它最大的问题。

**本 Skill 不重新研究法律问题。** 它只回答三件事：每条引注站不站得住、哪些错误动摇结论、这份文稿现在能不能发。

## 第 0 步：拿到文稿（阻塞闸门）

**没有待核内容就没有核验。** 这是本 Skill 唯一的硬前提，也是它替代的两个旧 Skill 最大的失败模式——提示词里只有"帮我核一遍"，手上却没有任何引注，于是输出一份空模板。

**必须先拿到下列之一**，否则不开工：

- 文稿正文（最好）
- 引注密集的段落（结论段优先）
- 引注清单（法规名 + 条号 + 文中如何表述）

**拿不到全文时**，明确告知："我只能核你给我的这部分。未提交的段落一律不在核验范围内，底稿里会写明。"——**不得对未见过的内容作任何判断，也不得因为看了结论段就说"全文引注无重大问题"。**

同时问齐这四项，每一项都会改变核验结果：

| 必问 | 为什么 |
|---|---|
| **文书类型与去向** | 诉讼文书、监管回复、对客户的意见书、内部备忘，可引范围与严格度不同（见 [citability.md](./references/citability.md)）。**发给监管和发给自己人，标准差一个量级** |
| **法律事实发生的时间** | 决定应当适用新法还是旧法。**跳过这一项会把正确的旧法引用误判为错误**，见第 2 步 |
| **签发时限** | 决定核验顺位。时间不够时先核什么，见 [severity-and-disposition.md](./references/severity-and-disposition.md) |
| **哪几段是结论** | 结论段的引注优先级最高——那里出错才会动摇结论 |

**角色**：读 `profile.md`（如已配置）。未配置时按「企业法务」处理并标 `[临时—未配置执业档案]`。机制见 [PROFILE.md](./references/PROFILE.md)。**角色不能用来降低签发闸门**——它只能让闸门更严。

## 第 1 步：抽取引注清单（含无源命题）

把文稿里所有引注抽出来编号。三类都要抽，**第三类最容易漏且最危险**：

1. **显性法规引注**：写明了法规名称与条号的。
2. **案例引注**：案号、案件名称、"最高人民法院指导案例 XX 号"、"某某公报案例"。
3. **无源命题**——**本 Skill 的重点**：

> 「根据相关法律规定……」「依照有关司法解释……」「按照现行法律规定，公司应当……」「法律要求……」

这类表述**没有任何条号可核，所以任何引用核验工具都发现不了它们**——`citation-validator` 只能核你给它的条号，识别不出"这句话根本没给出处"。但它们和显性引注一样在支撑结论，而且往往支撑的正是最关键的那句。

**处理方式**：逐条列出，标 `⬜ 无源—须补出处或降级表述`。要求文稿作者二选一：补上具体条号，或把表述从"法律规定"降级为"通常理解／商业惯例／我们的判断"。

**不得因为一句话听起来像常识就放过它。** "公司减资应当通知债权人"听起来是常识，但写进对外文稿就需要出处。

---

## 第 2 步：时间锚定（在核时效性之前做）

**引用已废止的法律不一定是错误。** 这是 naive 核验最典型的误判，也是本 Skill 与旧版最重要的差别之一。

> **《最高人民法院关于适用〈中华人民共和国民法典〉时间效力的若干规定》第一条** `[已核—2026-07-29]` `[法宝法规库]` · [法宝原文](https://pkulaw.com/chl/08f66078eb2ab58dbdfb.html) · 现行有效
> 「民法典施行后的法律事实引起的民事纠纷案件，适用民法典的规定。
> **民法典施行前的法律事实引起的民事纠纷案件，适用当时的法律、司法解释的规定**，但是法律、司法解释另有规定的除外。
> 民法典施行前的法律事实**持续至**民法典施行后，该法律事实引起的民事纠纷案件，适用民法典的规定，但是法律、司法解释另有规定的除外。」

**所以：一份处理 2019 年合同争议的文稿引用《合同法》，是正确的；把它改成《民法典》才是错的。**

第 3 步核时效性之前，先确定：

- **法律事实发生于何时**（合同签订、侵权行为、行政行为作出等）
- 该法律事实**是否持续**至新法施行之后
- 有无"法律、司法解释另有规定"的特别衔接规则

**输出要求**：对每条引用了非现行规范的引注，结论必须写成 `✅ 适用旧法—正确`、`🟠 应改引现行规范` 或 `⬜ 时间锚定不明—须确认法律事实时间`，**不得一律写"该法规已废止"了事**。

新旧法衔接不明时标 `⬜`，不猜。

---

## 第 3 步：逐条核验

读 [audit-dimensions.md](./references/audit-dimensions.md)，按九个维度逐条跑。摘要：

| # | 维度 | 一句话 |
|---|---|---|
| 1 | 存在性 | 这份规范／这个案号真的存在吗 |
| 2 | 版本与时效性 | `timeliness` 是什么；**部分失效时须核所引条文是否在失效范围内** |
| 3 | 条号 | 条号迁移是最高频错误（民法典编纂、民诉法修正、著作权法修正） |
| 4 | 条文内容 | 引述与原文是否一致；**逐字引用必须逐字** |
| 5 | 整条引用 | 法释〔2009〕14 号第一条要求"需要引用具体条文的，应当整条引用" |
| 6 | **命题对应性** | 这条法条真的支持这句话吗——**见第 4 步，最重要** |
| 7 | 可引性与层级 | 这类文件能不能作为依据引，还是只能用于说理——见 [citability.md](./references/citability.md) |
| 8 | 引据的上位法 | 该文件本身 `现行有效`，但它引的上位法还在吗 |
| 9 | 格式 | 名称是否完整、有无文号、有无法宝链接、指导性案例有无注明编号 |

**每一条核验结论都必须来自本次 MCP 返回。** 凭记忆判断"这条我记得是对的"等于没核。

**"与本次返回一致"不等于"已完成法律审查"**——这是旧版写对了的一句话，保留：它只说明文字对得上，不说明用得对。用得对不对是第 4 步的事。

---

## 第 4 步：命题—引注对应性（最重要的一步）

**前三步都只在核"这条法条是不是这么写的"，这一步核"这么写的法条是不是支持了那句话"。**

意见书出事主要出在这里，而且它是唯一无法自动化的一步：条号、版本、原文都能靠工具比对，"这条支持这个结论吗"只能靠读。

逐条问：

1. **法条的射程覆盖本案事实吗**？条文的主体、行为、对象是否与文稿描述的情形一致，还是被悄悄扩大了。
2. **文稿的结论强度超出条文了吗**？条文写"可以"，文稿写成"应当"；条文是原则规定，文稿当成具体裁判规则；条文有例外或但书，文稿只引了前半句。
3. **条文里的但书和例外被引了吗**？**只引对己方有利的前半句、省略但书，是本域最常见的实质性错误**，而且它能通过前三步的全部检查——原文照抄、条号正确、现行有效。
4. **中间推理步骤有没有被跳过**？从"法条这么规定"到"所以本案应当如此"之间，往往缺了事实认定或价值判断，而那一步才是真正有争议的地方。

判定三态：`✅ 支持`、`🟠 支持有限—需限缩表述`、`🔴 不支持—该结论缺依据`。

**判 `🔴` 时必须写清"这条法条实际管的是什么"**，不能只说"不支持"。

---

## 第 5 步：结论层核验

引注全对，结论仍可能有问题。逐项过：

- **结论是否超出全部依据的支撑范围**：把该结论涉及的引注加总，够不够撑起这句话。
- **有无绝对化表述缺乏依据**：「必定」「一定不会」「不存在任何风险」「百分之百合法」。法律结论几乎不存在这种确定性，出现即须改写。
- **有无遗漏对我方不利的规范**——**这一项必须主动查**。文稿只引支持自己的法条、不提相反规定，在对外文稿里是实质风险：对方或监管一定会引出来。检索时须专门反向搜一次。
- **有无模糊合规表述**：「基本符合」「原则上可以」「应无重大障碍」。见 [guardrails.md](./references/guardrails.md) 第十节。
- **地方口径有没有被写成全国规则**：本项目已多次发现这一错误。

---

## 第 6 步：分级与签发处置

读 [severity-and-disposition.md](./references/severity-and-disposition.md)。四级：

| 级别 | 含义 | 处置 |
|---|---|---|
| 🔴 **动摇结论** | 改了之后结论要重写 | **不得签发**，须回到实体分析 |
| 🟠 **须修正后签发** | 引注有实质瑕疵但结论方向不变 | 逐条给改法，改完可发 |
| 🟡 **建议修正** | 格式、顺序、完整性 | 不阻塞签发，列入清单 |
| ⬜ **无法核验** | 检索不到、MCP 不可用、时间锚定不明 | **明确标注为未核**，不得写成"已核通过" |

**签发结论必须落到三态之一，写在底稿最前面：**

- `可以签发`——无 🔴，🟠 已全部给出改法
- `修正后可签发`——列明必改项
- `不得签发`——存在 🔴，列明哪几处动摇了哪个结论

**⬜ 项不得被折算为通过。** 一份有 5 处无法核验的底稿，结论不能是"可以签发"，应写成"修正后可签发，另有 5 处未核，签发人须自行判断是否承担该风险"。

## 第 7 步：输出

按 [template.md](./template.md) 输出。

### 交付物纪律

- 元信息收进交付物**上方一个** `⚠️ 审阅提示` 块，第一行就是签发结论三态。
- **核验范围必须写明**：核了哪些段落、哪些没核。**这一项不能省**——签发人据此承担剩余风险。
- 每条引注附法宝链接与 `timeliness`，取自本次 MCP 返回的 `url` / `Url` 字段，不得拼接或凭记忆写 gid。
- **"通过"只表示与本次返回一致，不等于已完成法律审查**，且不替代承办人签发责任。
- 🔴 项必须写清动摇了哪一句结论，不能只说"该引注有误"。
- 无源命题单列一节，不与显性引注混在一起——它们需要的动作不同。

### 本 Skill 不做什么

- **不替签发人决定发不发。** 给出三态结论与理由，签发责任仍在承办人与所内流程。
- **不重新研究法律问题。** 判 🔴 之后指出缺口，不顺手把实体分析重做一遍（那是别的 Skill 的活）。
- **不改写文稿。** 给改法建议，不直接产出新版本文稿——除非用户明确要求。
- **不核事实与数据。** 金额、日期、主体名称的准确性不在本 Skill 范围，但**发现明显矛盾时应当提出**。
- **不出具法律意见。**

## 失败与降级

| 情况 | 怎么做 |
|---|---|
| **没有文稿或引注清单** | **不开工**。说明需要什么，给出三种最低输入形式。**不得输出空模板** |
| 只拿到部分段落 | 照核，但核验范围一节必须写明未核部分，签发结论加"仅限已核范围" |
| 法律事实时间不明 | 所有涉及新旧法的引注标 `⬜ 时间锚定不明`，**不得一律判为"已废止"** |
| 法宝 MCP 不可用 / 未订阅 | 仍可完成第 1 步（抽取引注与无源命题）、第 4 步（命题对应性，靠读）、第 5 步（结论层）——**这三步不依赖检索，且第 4 步价值最高**。但全部时效性、条号、原文核验标 `⬜ 未核验`，签发结论只能是"未完成核验，不得据本底稿签发" |
| `citation-validator` 命中失败 | 改用 `fatiao` 取原文人工比对；仍不行则标 `⬜`，**不得写"引用准确"** |
| 检索不到某规范 | 写"本次未检索到该名称的规范性文件"，并列出可能的原因（名称有误／已废止未入库／属内部文件／可能不存在）。**"未检索到"不等于"不存在"，但对外文稿中引用无法核实的依据本身就是风险**，须提示 |
| 案例被改判或再审撤销 | 直接判 🔴——引一个被推翻的判决支撑结论，比不引更糟 |
| 用户催"来不及了，你就说能不能发" | 按 [severity-and-disposition.md](./references/severity-and-disposition.md) 的顺位先核结论段与 🔴 候选，给出**限定范围**的结论，并写明未核部分。**不得为赶时间给出无范围限定的"可以发"** |
